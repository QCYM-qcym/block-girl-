# Cube Orientation Presentation Spec — production preparation only

2026-09-12。本轮不生产正式 Sprite；此规格供后续定向重制审批与实现，不包含资产完成声明。

## 身份与变换

CubeOrientation 的 right/up/forward 是 local 三基向量的世界方向，共24个右手正交整数姿态。FACE_ID 永久是 local+Z，即 physical_face_front；其他5个物理面不能复制脸。世界坐标 X east、Y top、Z south。North滚动后 +Z→+Y→-Z→-Y→+Z。East滚动会绕-Z，开始时+Z面法线保持south但脸上的图案会在其面内转动，不能把法线不变误当整个姿态不变。

一个静态选择键必须包含完整三轴 Orientation 和 View，不能仅用 Face World Direction（忽略了面内四种旋转）。皮肤是单独材质选择。四 View 是观察变换，不改变逻辑姿态。每一帧从 `orientation`、当前 `direction/fraction` 与 `view.displayed_angle()` 派生；临时 Presenter 不持有可变 visual_orientation。

当前同高地图投影 x'=16(x-z)、y'=8(x+z)-20y，观察向量为(1,0.8,1)。可见面法线点乘观察向量>0才画；脸背对相机或贴地隐藏。不能因世界/视角切换重置脸。X 技术标记有旋转对称性，只用于身份与可见性；最终人物面部通常不对称，必须保留面内方向。

## 资源数量与等价类

直接列举为24姿态×4View×2Skin=192个静态键。每View下，FACE位于TOP和两个朝向相机侧面可见，各有4个面内方向；背面两个方向与BOTTOM隐藏。

若其余五面完全相同、表面装饰不存在方向性且阴影固定于相机，则每相机皮肤可将12个隐藏脸状态合并为一个无脸立方体，得到 **13个静态外观**。这是条件性的最小模型，不适用于已有角色的非对称发丝/侧面纹理；不能先无依据认定这些状态等价。

在沿用当前固定相机光照、四View为整90°偏航的2D管线时，可把 CameraBasis×Orientation 化为24种相机相对姿态，跨四View复用一个规范表。稳妥上限每皮肤24个静态方向外观；两皮肤48个。是否可压缩到13须先给每个物理面定义完整材质并逐像素验证等价，不以X的对称性推断正式面部可合并。

每姿态4种相机相对滚动方向，共96条有向90°过渡/皮肤。若用与旧资源一致的6个采样角度 0、18、36、54、72、90°，两端复用静态外观，则上限24+96×4=408个原生图像/皮肤、两皮肤816。反向边或隐藏面过渡可继续去重，但先保证正确，不把四段默认起始动画复用于所有姿态。

旋转视角期间还有相机观察的连续中间角度。仅上述静态/滚动表不足以覆盖任意中间相机角度；可继续使用同一2D面投影器对六面像素材质动态投影，或者另行定义相机旋转采样及切换策略。需在正式生产前确定，不能用端态表假装覆盖全部过渡。

## 接缝与验收合同

滚动 t=0 精确是起始 O；t=1 精确是目标 O'。落定提交后读 O'，下一步从 O' 开始，不能先显示默认idle。Shift只替换对应物理面的材质。Reset恢复初始O。保存/谜题逻辑本轮不使用Orientation判定。

必须验收：24×4×2静态映射、每类过渡起止、4步循环、反向抵消、5秒停留、hold相邻接缝、View改变可见性、Shift保面、P01完整通关。正式图集维持透明、Nearest、统一像素密度和固定脚点，不旋转整张Sprite替代立体面的投影。

本轮临时实现：game/player/cube_visual_presenter.gd 继承已验证2D多边形投影，只在唯一面画X；既有正式PNG与SpriteFrames未修改。最终角色美术仍 **REWORK_REQUIRED**，不自动进入生产阶段。
