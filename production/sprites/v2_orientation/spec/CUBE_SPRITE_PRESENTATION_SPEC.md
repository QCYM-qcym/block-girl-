# CUBE_SPRITE_PRESENTATION_SPEC

2026-09-12。依据用户已冻结的正式资源重制要求；不改 gameplay，不提交 Git。

## 固定身份与复用

六面：FRONT=local+Z=CHARACTER_FACE，BACK=-Z，LEFT=-X，RIGHT=+X，TOP=+Y，BOTTOM=-Y。只有 FRONT 有脸。其余五面共用无方向性、无脸的发色材质；因此它们之间可视觉等价。完整 right/up/forward 24 态仍由既有 CubeOrientation 提供，不能只记录面法线。

每相机可见三个法线：NORTH 为 TOP/EAST/SOUTH；EAST 为 TOP/WEST/SOUTH；SOUTH 为 TOP/WEST/NORTH；WEST 为 TOP/EAST/NORTH。可见 FRONT 的3方向各有4种面内旋转，形成12种外观；FRONT隐藏的12姿态合并为1种无脸外观。因此24逻辑姿态对应每皮肤13种稳定外观。四视角通过 CameraBasis×Orientation 化为同一规范相机下的24态，不生产四套。两皮肤共26种稳定外观，最终由图像哈希验证是否有像素分辨率导致的进一步等价。

Front 位于顶面显示向上投影的脸，位于近侧显示侧面投影，位于背面/远侧/底面隐藏。过渡临界角允许只剩部分面部像素；不补脸、不镜头对齐。

## 正式美术

两套16×16正交物理面纹理：Mutsumi 灰绿低饱和发色、浅灰绿脸、小而安静的五官；Mortis 银灰/冷灰绿、深蓝灰边、小面积紫色面具式标记，表情克制。没有四肢、装备、文字、恐怖元素。先用 imagegen 生成物理正面设计，再像素清理、色板量化和网格规范化；原稿不标 GODOT_READY。

其余五面共用该皮肤的纯发色，不添加会破坏等价性的发丝方向纹理。两皮肤共享几何、UV、轮廓、尺寸和pivot，仅颜色/脸部纹理改变。

沿用旧正式Sprite的24×24透明RGBA画布、pivot=(12,21)、静止约16×16外接框，与32×16 tile保持原比例。上一阶段X方块为放大技术几何，不作为正式角色尺寸基线。Alpha只允许0/255、Nearest、无mipmap、无模糊；生产图不带标签和棋盘。先验证稳定与过渡边界可容纳于24×24，不擅自放大画布。

## 生成与运行映射

离线从固定六面材质投影生成稳定PNG，再验证全部24×4×2稳定映射。稳定通过后才生成90°roll的3个中间角22.5/45/67.5度，起止引用稳定态，合计5个采样。相邻反向roll复用逆序图像；再按精确RGBA哈希跨状态去重，保留明确mapping，避免手工制作24×4套。

相机旋转另从同一材质生成整90°偏航的中间帧，与相机progress对应，覆盖鼠标预览和回弹，不瞬间把脸转回镜头。旋转与移动互斥沿用现有控制器。所有中间图共享固定画布/pivot，成对皮肤alpha完全一致。

Player visual system持有只读图集和key→region lookup；每帧读取既有orientation/view/movement phase，O(1)查表。不会在P01脚本写映射，不新增逻辑姿态。调试字段同时给出当前采样帧与逻辑姿态；离散动画中间视觉是量化采样，落地必须精确等于逻辑终点。

独立正式Sprite场景复用原测试fixture控制器，保留原X场景不变，并用同一mover/view并排驱动正式角色和X基准。P01只替换Presentation引用和去除临时美术说明。
